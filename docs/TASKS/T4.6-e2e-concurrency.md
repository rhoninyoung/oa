# T4.6 — E2E: 并发乐观锁 + 完整链路通知验证

## 目标

Playwright E2E：双 Tab 并发编辑乐观锁冲突、submit→approve→reschedule 全链路通知验证。

## 前置

- T2.7（T4.1、T4.2）、T3.4 完成

## 命中的用例 ID

- E2E-LOCK-01
- E2E-NOTIF-01

## 场景步骤

### Part A — 并发乐观锁

1. GL Tab1 打开排期表，开始编辑任务 A（version=1）
2. GL Tab2 打开同一排期表，提交草稿（version=1 → version=2）
3. Tab1 尝试提交草稿（version=1）
4. 断言出现版本冲突提示弹窗
5. 提供「刷新」和「合并」按钮

### Part B — 完整链路通知

6. 完成 submit → approve → reschedule 全流程
7. 访问 `/dev/outbox` 页面（或调用 GET `/dev/outbox` API）
8. 断言有 4 条 notification，`dispatchedAt` 均非空：

   - submit → SCHEDULE_SUBMITTED
   - approve → SCHEDULE_APPROVED
   - reschedule → RESCHEDULE（给 GL）
   - plus GL withdraw 对应的 dismiss 记录
